1. 백엔드 전체 흐름

기본 요청 흐름

JSP / JavaScript
↓
Controller
↓
Service
↓
ServiceImpl
↓
DAO
↓
Mapper XML
↓
DB

조회 결과는 반대로 올라옴

DB
↓
Mapper XML
↓
DAO
↓
ServiceImpl
↓
Controller
↓
JSP 또는 AJAX

각 파일을 따로 외우는 것보다
"현재 데이터가 어디에서 와서 어디로 이동하는가"를 따라가는 것이 중요.


2. 각 계층의 역할

VO
-> 계층 사이에서 데이터를 전달하는 객체
-> 요청값, 조회조건, DB 조회결과 등을 담음
-> 직접 DB 조회나 업무처리는 하지 않음

Service
-> 해당 기능에서 제공해야 할 메서드를 정의하는 인터페이스
-> "무슨 기능을 제공할 것인가"를 정의

ServiceImpl
-> Service에서 정의한 기능을 실제 구현
-> DAO 호출
-> 필요한 경우 조건판단, 계산, 여러 DB 작업을 조합하는 업무 로직 처리

DAO
-> DB 접근 담당
-> Mapper XML에 있는 SQL을 호출

Mapper XML
-> 실제 SQL 작성
-> SELECT / INSERT / UPDATE / DELETE 수행

Controller
-> 사용자의 HTTP 요청을 처음 받음
-> 요청값을 VO에 받음
-> Session이나 입력값 확인
-> Service 호출
-> JSP 또는 JSON으로 결과 전달

JSP / JavaScript
-> 사용자 화면
-> Form 또는 AJAX로 Controller 호출

↓

↓

순서로 연결해서 생각.


4. VO와 매개변수

VO는 데이터를 여러 계층으로 전달하기 위한 객체.

메서드의 () 안에 들어가는 것은 매개변수.

BoardVO boardVO

BoardVO
-> 자료형

boardVO
-> 매개변수 이름

BoardSearchVO searchVO

BoardSearchVO
-> 자료형

searchVO
-> 매개변수 이름

즉

반환타입 메서드명(매개변수타입 매개변수명)

형태로 메서드를 읽으면 됨.


5. Getter / Setter

VO의 필드는 보통 private으로 선언하기 때문에
외부에서 Getter / Setter를 통해 접근.

Getter
-> 객체 내부의 값을 가져옴
-> 값을 반환해야 하므로 return 사용

Setter
-> 외부에서 받은 값을 객체 내부 필드에 저장
-> 값을 반환할 목적이 아니므로 void 사용

this.pageIndex=pageIndex;

this.pageIndex
-> 현재 객체의 실제 필드

pageIndex
-> Setter의 매개변수

즉 전달받은 값을 현재 객체의 필드에 저장하는 구조.


6. 반환타입과 void

반환타입은 메서드를 호출한 쪽에 어떤 결과를 돌려줄지를 의미.

BoardVO
-> 객체 한 개 반환

List<BoardVO>
-> 객체 여러 개 반환

int
-> 숫자 반환

String
-> 문자열 반환

void
-> 메서드는 실행하지만 결과값을 호출한 쪽에 반환하지 않음

void라고 아무 작업도 하지 않는 것은 아님.
INSERT, UPDATE 같은 DB 작업을 실행하고 끝낼 수도 있음.


7. List와 Generic

List
-> 여러 개의 데이터를 담는 자료구조

List<BoardVO>
-> BoardVO 객체 여러 개를 저장

<BoardVO>는 변수가 아니라
List 안에 어떤 타입을 넣을 것인지 지정하는 Generic 타입.

조회 결과가 여러 행이면 보통 List 사용.

selectList()
-> 여러 행 조회

selectOne()
-> 한 행 또는 하나의 값 조회


8. interface와 implements

Service는 주로 interface로 작성.

interface
-> 실제 실행코드보다 "이 기능이 있어야 한다"는 규칙 정의

ServiceImpl에서

implements Service

를 사용하여 실제 기능을 구현.

Service
-> 무엇을 할 것인가

ServiceImpl
-> 어떻게 처리할 것인가


9. extends와 상속

extends
-> 다른 클래스의 기능을 상속받음

BoardDAO extends EgovAbstractMapper

-> EgovAbstractMapper의 DB 관련 메서드를 사용 가능

selectList()
selectOne()
insert()
update()
delete()

BoardServiceImpl extends EgovAbstractServiceImpl

-> 전자정부프레임워크 Service 기본 클래스를 상속


10. Spring Bean과 @Resource

@Controller
@Service
@Repository

등이 붙은 클래스는 Spring이 객체를 생성하고 관리.

이 객체를 Spring Bean이라고 함.

@Service("boardService")
-> boardService라는 이름의 Bean 등록

@Repository("boardDAO")
-> boardDAO라는 이름의 Bean 등록

@Resource(name="boardDAO")
-> 이름이 boardDAO인 Spring Bean을 찾아 변수에 자동 연결

즉 Service나 DAO를 직접 new 하지 않고 Spring이 연결.

이 방식을 의존성 주입(DI)이라고 함.


11. 자주 사용하는 Annotation

@Controller
-> Controller 클래스 등록

@Service
-> Service 구현 클래스 등록

@Repository
-> DAO 클래스 등록

@Resource
-> Spring Bean 주입

@Override
-> 인터페이스나 부모 클래스의 메서드를 재정의

@RequestMapping
-> URL과 Controller 메서드 연결

@RequestMethod.POST
-> POST 요청만 처리

@ModelAttribute
-> HTTP 요청값을 VO에 자동 저장

@ResponseBody
-> return 값을 JSP 이름이 아닌 HTTP 응답 데이터로 직접 반환

@Transactional
-> 여러 DB 작업을 하나의 트랜잭션으로 묶음


12. DAO와 Mapper 연결

DAO에서

selectList("boardDAO.selectBoardList",searchVO)

형태 사용.

boardDAO
-> Mapper XML의 namespace

selectBoardList
-> Mapper XML의 id

Mapper XML에서

<mapper namespace="boardDAO">

<select id="selectBoardList">

두 값을 합쳐

boardDAO.selectBoardList

로 해당 SQL을 찾음.

두 번째 매개변수 searchVO는 Mapper SQL에 전달할 값.

Mapper에서는

#{property명}

형태로 VO 값을 사용.


13. ServiceImpl의 중요한 역할

단순한 기능에서는

ServiceImpl
↓
DAO 호출
↓
결과 반환

정도로 끝날 수 있음.

하지만 실제 ServiceImpl의 중요한 역할은 업무 로직 처리.

예를 들어 추천 기능

게시글 존재 확인
↓
현재 추천 여부 확인
↓
이미 추천했으면 삭제
↓
추천하지 않았으면 등록
↓
현재 추천수 다시 조회
↓
결과 반환

DAO
-> DB 작업 담당

ServiceImpl
-> 어떤 DB 작업을 어떤 순서와 조건으로 실행할지 판단


14. Controller의 주요 역할

Controller는 사용자 요청을 받아 전체 흐름을 시작.

주요 기능

요청 URL 연결
요청 파라미터를 VO에 저장
로그인 Session 확인
입력값 검증
Service 호출
JSP에 결과 전달
JSON 반환
redirect 처리
파일 업로드/다운로드 처리


15. ModelMap

Controller에서 JSP로 데이터를 전달할 때 사용.

model.addAttribute("board",result);

-> board라는 이름으로 JSP에 result 전달

JSP에서는

${board}

형태로 접근.


16. return과 redirect

return "board/boardDetail";

-> ViewResolver를 통해 JSP 화면으로 이동

return "redirect:/board/selectBoardList.do";

-> 현재 JSP를 직접 보여주는 것이 아니라
브라우저에게 해당 URL을 다시 요청하도록 함.


17. Session

Session
-> 서버에서 로그인 사용자의 상태를 유지

로그인 성공 후

session.setAttribute()

로 사용자 정보를 저장.

다른 Controller에서는

session.getAttribute()

로 로그인 정보 확인.

getAttribute()의 반환형은 Object이므로 필요한 타입으로 형변환.

로그아웃 시

session.invalidate();

-> Session 전체 만료

게시글 작성, 댓글, 추천 같은 기능에서
사용자 번호는 Form 값보다 Session 값을 사용하는 것이 중요.


18. Cookie

Cookie
-> 브라우저에 값을 저장

현재 프로젝트에서는 ID 저장 등에 사용.

new Cookie()
-> Cookie 생성

setPath()
-> Cookie를 사용할 경로 설정

setMaxAge()
-> Cookie 유지시간 설정

setMaxAge(0)
-> Cookie 삭제

Session
-> 서버에서 로그인 상태 관리

Cookie
-> 브라우저에서 값 저장


19. JSON

JSONObject
-> 하나의 JSON 객체

jObject.put("key",value)

-> JSONObject 안에 key:value 형태로 값 추가

JSONArray
-> 여러 JSON 데이터를 배열 형태로 저장

ObjectMapper
-> Java 객체를 JSON 문자열로 변환

PrintWriter
-> 완성된 JSON 문자열을 HttpServletResponse를 통해 브라우저로 직접 전송

23. GET / POST

GET
-> 주로 조회
-> URL에 요청값이 포함될 수 있음

POST
-> 등록/수정/삭제 등 서버 데이터를 변경하는 작업에 주로 사용

현재 프로젝트에서도 등록/수정/추천/댓글/로그인 등은 POST를 주로 사용.


24. HttpServletRequest / HttpServletResponse

HttpServletRequest
-> 사용자가 서버로 보낸 HTTP 요청정보 사용

HttpServletResponse
-> 서버가 브라우저로 보낼 HTTP 응답을 직접 제어

JSON 응답
파일 다운로드
HTTP 오류 응답

등에서 사용.


25. try / catch / throws

try
-> 오류가 발생할 수 있는 코드 실행

catch
-> 오류가 발생했을 때 직접 처리

e.printStackTrace()
-> 오류 내용을 Console에 출력

throws Exception
-> 현재 메서드에서 처리하지 않은 예외를 호출한 쪽으로 넘김


26. @Transactional

여러 DB 작업을 하나의 작업 단위로 묶음.

작업 도중 오류 발생 시
일부 DB 작업만 반영되는 것을 막기 위해 사용.

여러 INSERT / DELETE / UPDATE가 연속되는 업무 로직에서 중요.


27. Integer와 int

int
-> 기본자료형
-> null 불가능

Integer
-> 객체형
-> null 가능

조건 자체가 없는 상태를 표현해야 하면 Integer를 사용할 수 있음.

null
-> 값 또는 조건이 존재하지 않음

0
-> 실제 숫자 0

둘은 의미가 다름.


28. 객체 비교

기본자료형 값 비교

==

String, Long 같은 객체의 실제 값 비교는 보통

equals()

사용.

!uiIdx.equals(result.getUiIdx())

-> 두 값이 서로 다름.

33. 직접 기능을 작성할 때 생각할 것

1) 화면에서 어떤 요청을 보낼 것인가
2) Controller가 어떤 값을 받아야 하는가
3) VO에 어떤 데이터가 필요한가
4) Service에서 어떤 기능을 정의할 것인가
5) ServiceImpl에 업무 로직이 필요한가
6) DAO에서 어떤 DB 작업을 해야 하는가
7) Mapper에 어떤 SQL이 필요한가
8) 결과가 한 건인지 여러 건인지
9) 반환타입이 VO / List / int / void 중 무엇인지
10) JSP 전체 화면을 반환할지 JSON만 반환할지
